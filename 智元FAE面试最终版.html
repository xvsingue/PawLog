岗位理解 · 项目经历 · 场景问题，三类问题一条线打通。不背理论，只练“先做什么、用什么工具、怎么说话”。

面试前 30 分钟怎么用

1）背下“一句话定位 + 30 秒自我介绍”；2）挑两个项目套进“问题→动作→工具→结果→沉淀”；3）把 6 个场景题的骨架读两遍；4）最后扫技术速记和反问，不要临时补理论。

一条总原则：FAE 面试考的不是推导公式，而是 ①遇到问题先做什么 ②用什么工具取证 ③怎么跟客户和研发说话。每个回答都要有“动作”和“证据”。

PART 1

岗位理解类

别答成“技术支持就是修机器”

1.1FAE 到底是做什么

通用定义：FAE 是客户和研发之间的技术接口，把“产品卖出去”变成“产品用起来”。

放到智元，按官方 JD 拆成四块：

  • 交付：客户现场整机安装、系统部署、IMU 与关节等参数标定、现场验收。
  • 救火：接售后升级的复杂问题，现场或远程支援；硬件电路、软件逻辑、系统级定位。
  • 沉淀：故障案例集、FAQ、维护手册、SOP，把共性问题反哺研发。
  • 赋能：把研发规范翻译成销售和售后能用的文档，并做培训。
一句话：让机器人到客户那儿能安全、稳定、可复现地跑起来。

1.2为什么选择 FAE

不要说“研发太卷”。按三层讲：

  • 行业：人形机器人正从样机走向批量交付，公开信息显示智元已实现第 20000 台通用具身机器人下线，交付端正在缺人。
  • 公司：整机 + 灵巧手 + 关节模组 + 数据与模型的全栈布局，FAE 能接触最完整的产品面。
  • 我自己：坐得住现场，也喜欢把问题闭合；比起只做仿真，更擅长在真实系统里定位问题，这恰好是 FAE 的核心。
如果被问“为什么不做研发” “研发是把东西做出来，FAE 是确保它在真实环境里能用。我对后半段更感兴趣，也更擅长。”

1.3你理解的 FAE 核心能力

  1. 排障思路：能分层、能收敛，不靠猜。
  2. 动手能力：会用万用表、示波器、逻辑分析仪，会看日志、会抓包。
  3. 技术翻译：对客户讲人话，对研发讲证据。
  4. 闭环与沉淀：问题解决完要变成文档，让别人也能处理。

补一句：还有抗压和出差，这是这个岗位的日常，不是额外要求。

1.4一句话定位（背下来）

“我是能把硬件问题用仪器测出来、把软件问题用日志定位到模块、并且能把过程写成别人能复用的文档的人。”

1.5自我介绍：30 秒 / 90 秒

结构30 秒（HR / 开场）90 秒（技术面）
我是谁 学校 + 专业 + 一句话方向。 同上，补一句做过什么类型的板子或系统。
我做过什么 一个最硬的项目，说清我负责哪块。 两个项目：一个偏硬件调试，一个偏系统联调，各带一个数字（通道数、良率、定位时长）。
我为什么来 想做离产品最近、离客户最近的工程岗。 人形机器人进入交付期，FAE 是把技术变成可用产品的关口，我想站这个位置。
我能带来什么 上手快、能出差、能写文档。 仪器 + 电路 + 脚本三件套，能把一次救火变成一套 SOP。
节奏：每段不超过 3 句，说完停 1 秒，留一个钩子让对方追问。
PART 2

项目经历类

细节比规模重要

2.1包装公式：所有项目都用这一个

问题 → 我的动作 → 用的工具 → 结果（数字）→ 沉淀

三个硬要求：

  • 第一人称，说“我”做了什么，不说“我们”。
  • 每个判断都要有依据：测出来的、看出来的、查出来的。
  • 结尾一定落到“防再发”。

2.2没有大项目怎么办

课程实训、毕设、实验室设备调试、竞赛联调都能用，按下面三个模板改写。

模板 A｜课程实训：板子不工作

  • 问题：焊接完成后上电无输出。
  • 动作：分段测量，先量供电，再量关键节点电压，对照原理图缩小范围。
  • 工具：万用表、示波器、原理图。
  • 结果：定位到虚焊 / 电源时序 / 器件方向问题，修复后功能正常。
  • 沉淀：整理了一份上电检查清单。

模板 B｜设备调试：通信不通

  • 问题：设备与上位机通信时通时断。
  • 动作：先查线序和波特率，再查终端电阻，最后抓报文看有没有错误帧。
  • 工具：万用表、逻辑分析仪 / 串口助手。
  • 结果：定位到接线或终端电阻问题，通信稳定。
  • 沉淀：写了接线与参数核对表。

模板 C｜竞赛或小系统联调：偶发故障

  • 问题：系统跑一段时间偶发死机。
  • 动作：加日志、记录时间和环境，反复复现，用排除法一次只改一个变量。
  • 工具：日志、示波器、替代法换件。
  • 结果：定位到供电或散热问题，复现率降为 0。
  • 沉淀：补充了长时间跑机测试项。
注意 不要编。把真实做过的事按结构讲清楚，细节比规模重要。

2.3两个 STAR 故事，各准备一个

故事一：靠“测量”定位（硬件向）

  • S：客户或老师催，时间紧，只能一个人上。
  • T：判断是供电、信号还是器件问题。
  • A：先量供电，再看关键波形，逐一排除，换件验证，一次只改一个变量。
  • R：定位到根因，恢复时间 X 小时，写了复盘。

故事二：靠“日志和代码”定位（软件向）

  • S：现场偶发失败，无法长时间停留。
  • T：要在离开前拿到可分析的证据。
  • A：打开日志级别、录包、记录操作步骤，回去复现后定位到某个模块或配置。
  • R：远程给出方案，问题闭环，形成排查步骤。

2.4必被追问的 5 个问题

  • “具体你做了什么？” → 说动作和工具，不说职责。
  • “你怎么排除其他可能的？” → 假设 → 验证 → 结果，这是加分点。
  • “如果最后没解决呢？” → 讲止损、升级、留证据，不装成功。
  • “这个数字怎么来的？” → 说清测量方式和口径，别拍脑袋。
  • “团队里你贡献多少？” → 明确边界，不抢功也不贬低队友。

2.5面试前要准备好的“证据”

  • 2 个项目各 1 张图（框图 / 波形 / 现场照）
  • 3 个数字：处理时长、定位环节、改善幅度
  • 1 份你写过的文档（调试记录、SOP 都行）
  • 想清楚：如果重来一次，你会先做什么
PART 3

场景问题类

这部分决定你能不能过

3.0万能答题结构（先背这个）

确认现象和范围谁、何时、什么操作、单台还是批次。
先保安全、先止损急停、备用机、降级方案。
分层定位供电 → 通信 → 驱动 → 配置 → 算法 → 机械。
用工具取证仪器、日志、抓包，留下证据再动手。
单变量验证一次只改一处，改完立刻回归。
闭环给方案、给时间点、写复盘。
沟通对客户讲结论和下一步，对研发讲证据和影响面。
场景 1客户反馈设备 / 芯片异常，你怎么处理？
  • 先问清：什么现象、什么时候开始、之前动过什么、单台还是多台。
  • 远程指导取证：拍照、录视频、导日志、量关键点电压。
  • 判断归类：使用问题 / 配置问题 / 接线问题 / 硬件失效 / 设计缺陷。
  • 先给临时方案让对方能继续用，再给根因和时间点。
  • 闭环后写案例，判断是否需要通知同批次客户。
一句总结：“先让客户能干活，再把原因找清楚。”
场景 2现场调试遇到难题，怎么推进？
  • 保交付优先：备用机、降级模式、绕过故障模块。
  • 缩小范围：换模块、换线、换端口、换整机，用二分法快速定位。
  • 带证据升级研发：现象 + 复现步骤 + 日志波形 + 已排除项 + 影响范围。
  • 现场记录：时间、操作、现象，别靠回忆。
  • 事后复盘：判断是偶发还是设计问题。
场景 3如何和客户沟通技术问题？

三段式：结论先行（现在什么状态、能不能用）→ 影响与方案（影响多大、临时怎么办）→ 下一步与时间（谁来做、什么时候给结果）。

四条纪律

  • 不用术语砸人，要能翻译成大白话。
  • 不确定的事不承诺，给区间也给条件。
  • 重要结论书面确认，避免口头扯皮。
  • 客户催的时候，先回应情绪，再回应问题。
场景 4客户不配合 / 现场条件差
  • 先找共同目标：交付验收、产线不停。
  • 把要求变成清单：谁、什么时候、提供什么。
  • 找对接口人，避免多头指挥。
  • 全程留痕：照片、记录、邮件。
  • 推进不了就按机制升级，不硬扛。
场景 5问题复现不了怎么办
  • 加日志、加记录，先让问题留下痕迹。
  • 给客户操作清单，规范复现路径。
  • 远程留观或安排回访，约定观察周期。
  • 用同批次设备做对比测试。
  • 明确告知：暂无法复现，但我们在怎么跟。
场景 6销售催、研发不理，怎么协调？
  • 用影响面说话：影响多少台、是否阻塞验收。
  • 分级：阻塞 / 严重 / 一般，按优先级排。
  • 走升级机制，抄送对应负责人。
  • 把口头变书面，形成待办和时间点。

3.7六步排障法（可以画在纸上讲）

定范围单台还是批次，偶发还是必现。
保安全急停、支撑、限速。
分层查供电 → 通信 → 驱动 → 配置 → 算法 → 机械。
取证仪器、日志、抓包。
单变量验证一次只改一处。
沉淀案例、FAQ、SOP。
加分句 “我判断问题是否真解决，标准不是‘现在能动了’，而是‘同样条件下复现不出来，并且别人照文档也能处理’。”
PART 4

技术速记

够说出口就行，不深挖

4.1关节模组

  • 构成：无框力矩电机 + 减速器 + 编码器 + 驱动器 + 抱闸。
  • 参数：减速比、额定与峰值扭矩、编码器分辨率、通信周期。
  • 标定：机械零位、方向、限位、力矩常数、摩擦补偿。
  • 故障：抱闸未松、零位漂、过流、过温、丢帧。

4.2IMU 标定

  • 静态零偏：静止采样取均值扣除。
  • 六面法：标加速度计零偏与标度因数。
  • 还要考虑温漂、安装误差、与关节零位联合标定。

4.3电源与安全链

  • 母线电压、上电时序、缓启动、保险、浪涌。
  • 急停回路、STO、抱闸供电。
  • 地环路是多点接地最常见的坑。

4.4总线

CAN

  • 两端各 120Ω，断电测约 60Ω。
  • 波特率一致，ID 不冲突，负载低于 70%。
  • 屏蔽层单点接地。

EtherCAT

  • 状态机 INIT → PREOP → SAFEOP → OP。
  • 关注 DC 同步和丢站，先怀疑线缆接头。

工具：candump、cansend、示波器差分探头。

4.5Linux 与 ROS2

Linux

dmesg -w、journalctl -u、ip a、ping、ethtool、tcpdump、df -h。

ROS2

ros2 topic list/echo/hz、node info、param、bag record/play、tf2_echo、rqt_graph。

三个坑：QoS 不匹配、ROS_DOMAIN_ID 冲突、忘了 source install/setup.bash。

回答程度要诚实 分三档说清：能做 / 学过 / 没做过，再补学习动作。

4.6公司产品（说 2 到 3 个即可）

  • 第 20000 台通用具身机器人下线。
  • 精灵 G2 Max：双臂合计负载 40kg，双电池热插拔。
  • OmniHand 灵巧手：16 自由度，约 510g。
  • 皮下式关节液冷系统。
别背成新闻播报，提 1 到 2 个就够。
