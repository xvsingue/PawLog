智元机器人 · FAE 面试速记卡
上海智元新创（AGIBOT）
整机交付 / 现场排障 / 技术赋能
========================================

【只剩 10 分钟，只看这 5 条】
1. 这个岗位不是卖芯片，核心是：把机器人
   交付到客户现场并跑起来——装、调、标定、
   排障、写文档、做培训。
2. 面试官最怕你只会读书。每个回答都要落到
   "我动手做过 / 我用仪器测过 / 我写过复盘"。
3. 背熟六步排障法：定范围 → 保安全 → 分层查
   → 取证 → 单变量验证 → 沉淀。
4. 模拟/电源背景是加分项：电源、信号链、
   EMC、示波器和万用表，正是现场定位硬件
   问题的底子。
5. 反问要问交付：客户结构、典型故障 Top3、
   出差比例、外包还是正式编制。


========================================
一、岗位画像：面试官在测什么
========================================

JD 拆成 4 块
· 交付：整机安装、系统部署、IMU 和关节等
  参数标定、现场验收。
· 救火：接售后升级的复杂问题，现场或远程
  支援；硬件电路 + 软件逻辑 + 系统级定位。
· 沉淀：故障案例集、FAQ、维护手册、SOP，
  反哺研发改设计。
· 赋能：把研发规范翻译成销售、售后能用的
  文档和培训。

对应的 5 项能力
· 仪器：万用表、示波器、逻辑分析仪。
  要会测、会读波形。
· 系统：Linux 常用命令 + ROS2 + 能读
  C/C++/Python。
· 机电：电机、减速器、编码器、IMU、
  驱动器的基本原理。
· 沟通：对客户讲人话，对研发讲证据。
· 韧性：出差、夜场、客户催交付时不崩。

一句话自我定位（可背）
"我是能把硬件问题用仪器测出来、把软件问题
用日志定位到模块、并且能把过程写成别人能
复用的文档的人。"

二、自我介绍：30 秒 + 90 秒
========================================

结构：我是谁 → 我做过什么 → 我为什么来
→ 我能带来什么。

30 秒版（HR / 开场）
· 学校 + 专业 + 一句话方向（硬件 / 机电 /
  嵌入式）。
· 一个最硬的项目，说清"我负责哪一块"。
· 想做离产品最近、离客户最近的工程岗。
· 上手快、肯出差、能写文档。

90 秒版（技术面）
· 同上，补一句做过什么类型的板子或系统。
· 两个项目：一个偏硬件调试，一个偏系统
  联调，各带一个数字（通道数、良率、
  定位时长）。
· 人形机器人正从样机走向批量交付，FAE 是
  把技术变成可用产品的关口，我想站这个
  位置。
· 仪器 + 电路 + 脚本三件套；能把一次救火
  变成一套 SOP。

提醒
每段不超过 3 句，说完停 1 秒看对方反应。
不要背成流水账，留一个钩子让面试官追问。


========================================
三、必答 6 问与回答骨架
========================================

1. 为什么选智元？为什么做 FAE 不做研发？
三层回答：
· 行业：人形机器人进入量产交付期，公开
  信息显示智元已实现第 20000 台通用具身
  机器人下线。
· 公司：整机 + 灵巧手 + 关节模组 + 数据
  和模型全栈，FAE 能接触最完整的产品面。
· 我自己：喜欢在现场把问题闭合，坐不住
  纯仿真。
不要说"研发太卷所以来做 FAE"，改成
"我更擅长在真实系统里定位问题，这恰好
是 FAE 的核心"。

2. 客户现场机器人上电后，某个关节不动作，
   你怎么查？（高频）
按层走，别乱拆：
① 安全：急停是否释放、是否在使能状态、
   周围是否允许动作。
② 供电：母线电压、驱动器指示灯、保险、
   抱闸供电。
③ 通信：CAN / EtherCAT 是否在线、有无
   报错帧、节点是否丢失。
④ 配置与标定：关节 ID、方向、零位、限位、
   减速比是否被改。
⑤ 软件：日志、报错码、控制模式、使能
   指令是否下发。
⑥ 机械：卡死、抱闸未松、线束磨损。
取证：万用表量供电、示波器看差分信号、
candump 看报文、ros2 topic echo 看状态、
dmesg 看驱动。
收尾：换件验证 → 记录到案例集 → 判断是
偶发还是设计缺陷。

3. 讲一个你定位并解决的硬件或系统问题
   （STAR）
· S 场景与约束：时间、人手、客户在等。
· T 你的具体任务，不是团队任务。
· A 怎么分层排查、用了什么仪器、排除了
  哪些假设（重点讲"排除"）。
· R 结果量化 + 沉淀：写没写文档、有没有
  防再发。
准备两个：一个靠测量定位，一个靠日志或
代码定位。

4. 现场交付在即，问题一时解决不了，客户
   在催，你怎么办？
先恢复、再根因：
· 启用备用机、降级方案或绕过故障模块，
  保证客户能验收。
· 明确告知：当前状态 + 下一步 + 时间点，
  不承诺做不到的事。
· 按升级机制拉研发。
· 事后 24 小时内出复盘。
关键词：止损优先、信息透明、升级及时、
闭环复盘。

5. Linux / ROS2 你到什么程度？（务必诚实）
用三档回答：能做 / 学过 / 没做过，别硬吹。
示例："日常能用 Linux 查日志、看设备、配
网络；ROS2 能跑节点、看 topic、录 bag、
看 tf；源码级改造还在学，但能读 C++ 或
Python 定位到模块。"
补一句学习证据：最近在跟的教程，或自己
搭过的仿真和小项目。

6. 能接受出差吗？抗压怎么样？
给具体，不表忠心："能接受短期出差，之前
做过需要外场调试的项目，连续几天在现场也
经历过；我的习惯是当天问题当天记录，避免
越积越乱。"


========================================
四、技术速记（会被追问细节）
========================================

关节模组
· 构成：无框力矩电机 + 减速器（谐波/行星）
  + 编码器 + 驱动器 + 抱闸。
· 关键参数：减速比、额定与峰值扭矩、编码器
  分辨率、通信周期。
· 标定内容：机械零位、方向、限位、力矩常数、
  摩擦补偿。
· 常见故障：抱闸未松、编码器零位漂、过流、
  过温、通信丢帧。

IMU 标定
· 静态零偏：静止采样取均值后扣除。
· 六面法：标定加速度计零偏与标度因数。
· 还要考虑温漂、安装误差矩阵，以及与关节
  零位的联合标定。

电源与安全链
· 母线电压、上电时序、缓启动、保险、浪涌。
· 急停回路、STO 安全转矩关断、抱闸供电。
· 接地与共模：多点接地引起的地环路最坑。

总线排查
CAN：
· 两端各 120Ω，断电测总线约 60Ω。
· 波特率一致、ID 无冲突、总线负载低于 70%。
· CAN_H / CAN_L 差分信号、屏蔽层单点接地。
EtherCAT：
· 状态机 INIT → PREOP → SAFEOP → OP。
· 关注 DC 同步、从站丢站按段排查。
· 网线和接头优先怀疑。
工具：candump / cansend、示波器差分探头、
总线分析仪。

Linux 常用
· dmesg -w、journalctl -u、ls /dev/tty*
· ip a、ping、ethtool、tcpdump
· top、df -h、udev 规则、权限与用户组

ROS2 常用
· ros2 topic list / echo / hz
· ros2 node info、ros2 param
· ros2 bag record / play、tf2_echo、rqt_graph
· 三个高频坑：QoS 不匹配（reliability /
  durability）、ROS_DOMAIN_ID 冲突、
  忘了 source install/setup.bash。


========================================
五、现场排障六步法（可画在纸上讲）
========================================

① 定范围
   单台还是批次？一直有还是偶发？什么操作
   之后出现？先复现。

② 保安全
   急停、支撑、限速；先让客户能继续用，
   备用机或降级。

③ 分层查
   供电 → 通信 → 驱动与固件 → 标定与参数
   → 上层算法 → 机械。

④ 取证
   仪器 + 日志 + 抓包，留下证据再动手，
   避免"修好了但不知道为什么"。

⑤ 单变量验证
   一次只改一处，改完立刻回归，排除巧合。

⑥ 沉淀
   案例集 + FAQ + SOP；能反哺设计的提给
   研发。

加分句
"我判断一个问题是否真的解决，标准不是
'现在能动了'，而是'同样条件下复现不出来，
并且别人照文档也能处理'。"


========================================
六、模拟 / 硬件背景怎么接上机器人
========================================

· 电源与模拟电路 → 整机供电、上电时序、
  浪涌、纹波、地环路；现场一大半所谓玄学
  故障，其实是电源和接地。
· 信号链与传感器 → 编码器、IMU、力与触觉
  传感器的输出异常，本质是信号链和噪声。
· EMC 与布线 → 总线丢帧、通信偶发失败，
  多半是屏蔽、双绞、共地没做好。
· 仪器使用 → 示波器、万用表、逻辑分析仪，
  JD 明确要求，这是你的直接优势。
· 客户支持经验 → 选型、调试、失效分析，
  本质就是"把技术翻译给客户"，与 FAE 同构。

如果被问"你没做过人形机器人怎么办"：
先承认差距，再给出补齐路径（关节与 IMU
标定、ROS2、整机安全流程），最后强调底层
方法可以迁移。
